## 브렌치 규칙

폴더구조

협업툴 가이드

1. 그라운드 룰 설정 (1순위)
    - 마크다운 문서로 작성해 보관할 것. 추후 Repository 개설 시 문서 폴더에 적재
    - 작업이 막혔을 때 
    - 구현기능 리뷰 절차
    - 일일회의 일정
    - 문서화 범위 (회의록, 기술문서, 일일 작업일지 등)

2. 프로젝트 기능 명세 (2명)
    - 프로젝트 기간 상 '반드시' 구현되어야 할 것과 기간이 남았을 때 추가로 도전할 것을 구분.
    - 어떤 방식으로 구현되어야 하는지까지 생각할 것이 아니라, 게임에 존재해야 하는 기능 단위까지만 명세

3. 에셋 확보 (나머지 인원)
    - 유니티에 실제로 임포트, 잘 적용 되는지 반드시 확인할 것.
    - 추가하기로 결정한 에셋을 명시한 마크다운 문서 작성 및 보관할 것.

4. 컨벤션 문서 작성 계획
    - 프로젝트에 적용될 컨벤션 문서는 어떤 것이 필요한지 리스트화
    - 러프하게 '코드 스타일', '커밋 메세지', '브랜치 관리' 같은 식으로 알아볼 수 있을 수준으로만 준비
